
# DBD MMR

## Развертывание на Render

1. Создайте Web Service из этого репозитория. Команда сборки: `npm ci`; команда запуска: `npm start`.
2. В настройках сервиса задайте переменные окружения:
   - `MONGODB_URI` — URI MongoDB Atlas с именем базы данных.
   - `STEAM_API_KEY` — ключ Steam Web API.
   - `SESSION_SECRET` — длинная случайная строка, используемая для подписи сессий.
   - `APP_URL` — публичный адрес сайта, например `https://ваш-сервис.onrender.com`, без завершающего `/`.
   - `NODE_ENV` — `production`.
3. Укажите адрес `APP_URL` как домен приложения в настройках Steam Web API. Callback должен быть `${APP_URL}/auth/steam/return`.
4. Разрешите Render подключаться к MongoDB Atlas и проверьте, что у пользователя базы данных есть доступ к нужной базе.
5. В Render укажите Health Check Path `/healthz`. Эндпоинт отвечает `200`, когда MongoDB доступна, и `503`, когда соединение потеряно.

Не добавляйте реальные ключи и URI в файлы репозитория. Если секреты уже попадали в исходный код или историю Git, замените пароль MongoDB, ключ Steam и `SESSION_SECRET` в настройках сервисов.

## Работа без засыпания

Бесплатный Web Service на Render засыпает после периода бездействия; приложение не может отключить это ограничение. Для постоянно доступного сайта переведите сервис на платный тариф Render с режимом Always On. Health check проверяет готовность, но не заменяет постоянно работающий тариф.

Сессии входа хранятся в MongoDB и действуют до 24 часов, поэтому перезапуск приложения не должен разлогинивать пользователей. Токен Behavior используется только на сервере и не включается в публичные ответы API.

Для локального запуска задайте те же переменные окружения и выполните `npm start`. По умолчанию сервер слушает порт `5000`.
